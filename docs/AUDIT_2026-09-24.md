## High

### H-1. The MLB Most Likely book could stake a hitter who never played — FIXED

- **Found:** `engine/mlb/pipeline` stamps `lineup_confirmed` on every
  prop. Its own comment says the board may show a projected hitter "with
  the caveat" and the journal waits for the lineup card.
  - The edge book waits upstream: an unconfirmed hitter is "On deck",
    not recommended.
  - The long-shot journal refuses him. On 2026-07-26, 31 of 58 journaled
    long shots were projected hitters who sat.
  - The Most Likely board reads *every* prop row, recommended or not.
    `likely._row_from` dropped the flag, and `ledger.log_most_likely`
    had no rule. That book has been staked with real money on MLB since
    2026-09-19.
- **Impact:** baseball has no absent-player grade
  (`ledger.ABSENT_RULE_SPORTS` is NFL and college only). A staked hitter
  who sat stays open for good. A morning build journals the top ten
  before any lineup card is out.
- **Fix:** the Most Likely row carries `lineup_confirmed`, and
  `log_most_likely` skips `False`. The row journals on the first build
  after the card posts, if it is still on top. The row shows a "Lineup
  not posted" chip, and the pick page names it under Worth knowing.
- **Box:** step 8b lists any MLB Most Likely rows already stuck open from
  before the fix.
- **Test:** `tests/test_a_projected_hitter_waits_for_his_lineup.py`.

### H-2. The Pick of the Day could lock onto a projected hitter — FIXED

- **Found:** the day's pick is locked by its first journal
  (`ledger.log_pick_of_the_day`), which had no lineup rule. A scratch
  would have locked the day to a pick that can never grade.
- **Fix:** the same rule. The pick is not journaled, so not locked, until
  his card posts.
- **Test:** the same file as H-1.

### H-3. Ask had no daily ceiling on spend — FIXED (numbers NEED ETHAN)

- **Found:** every Ask question is a paid model call. The only limit was
  8 a minute per address: 11,520 a day for one subscriber, or for one
  stolen session. `data/ask_usage.json` priced every call and nothing
  read the total.
- **Fix:** two limits, each an environment variable on the box; 0 turns
  either off.
  - `QB_ASK_PER_ACCOUNT_DAILY`, default **100** uncached questions per
    account per UTC day. A signed-out reader, with the paywall off, is
    counted by address.
  - `QB_ASK_DAILY_USD`, default **$25** of estimated spend per UTC day,
    after which Ask pauses site-wide until midnight UTC.
  - The log stores a one-way tag per account, never the account itself.
  - A capped reader sees a plain sentence saying when Ask resets.
- **Your call:** are 100 questions and $25 a day the right numbers?
  Step 8c prints the real daily spend so far.
- **Test:** `tests/test_ask_has_a_daily_ceiling.py`.

## Medium

### M-1. The Most Likely page opened on two screens of method — FIXED

- **Found:** on a phone, the whole first screen of the Most Likely page
  was four stacked blocks:
  - the board guide (AUC figures, "de-vigged", "z 0.75");
  - the real-money paragraph;
  - how the board is ranked;
  - the refusal census ("611 turned down") and the per-market funnel.

  The first pick sat about two screens down. The same two guide
  paragraphs sat between Home's "Qellys' top picks" heading and its
  first pick.
- **Fix:** `boardGuide` is now one line: what the board is picked on, the
  money chip, and "how we know" to open the rest. On the Most Likely
  page, "How it's ranked · and what it turned down" folds the other
  three blocks. Nothing was deleted. The first pick now shows on the
  first phone screen.

### M-2. The site's code is heavy on a first visit — RECOMMENDED

- **Found:** a first visit downloads about **1.13 MB compressed** before
  any board:
  - `app.js`: 2.2 MB raw, 727 KB gzip;
  - styles: 176 KB;
  - ApexCharts: 152 KB;
  - the page: 29 KB.

  Caddy compresses and revalidates the shell correctly, so repeat visits
  cost a 304. The first visit on a phone is the expensive one.
- **Measured:** removing comments alone takes `app.js` from **727 KB to
  404 KB gzip (−44%)**. The comments are the codebase's memory and stay
  in the repo; only the served copy would lose them.
- **Recommendation:** a deploy step that writes a comment-stripped copy
  for the browser, with `index.html` pointing at it. It needs a tool on
  the droplet (TypeScript's transpiler did it cleanly here) and a check
  that the served copy parses. Not done blind.

### M-3. Boards publish fields the page never reads — NEEDS BOX

- **Found:**
  - Every prop row carries its whole alternate ladder (`alt_lines`,
    `alt_sharp_lines`, `rung_probs`). The page never reads it; only the
    droplet's `potd_report.py` does.
  - `board_shelves` repeats every Most Likely row in full (27 KB against
    26 KB on the demo NFL board).
  - The code's own comments put the MLB board at 8 MB. The demo slates
    carry no ladders, so their share of the real boards could not be
    measured here.
- **Next:** `python3 homecheck.py weight` (step 8a) prints each board's
  size and its heaviest fields. If the ladders are the bulk, the fix is
  to drop them from the copy the page downloads and keep them in the
  droplet's private copy for the report tools. `board_shelves` can carry
  row references instead of copies.

### M-4. The content policy still allows inline script — RECOMMENDED

- **Found:** the site sends a strict Content-Security-Policy, but
  `script-src` includes `'unsafe-inline'` because the page carries **93
  inline handlers** (`onclick=` 79, `onerror=` 7, others 7).
  `server.py`'s own comment named this as known debt when it was 33.
- **Mitigation already in place:** every place feed or user text is
  written into HTML was checked (the 16 riskiest: account names, league
  names, draft names, message avatars, alert titles, market titles,
  headlines) and all of them escape. The session cookie is HttpOnly, so
  even a script could not read it.
- **Recommendation:** move the handlers to delegated listeners, which the
  page already uses elsewhere (`[data-open]`), then drop
  `'unsafe-inline'` from both copies of the policy: `server.py` and the
  Caddyfile, which a test keeps identical.

### M-5. Two colours read below the contrast bar — NEEDS ETHAN

- **Found** (`python3 contrast.py`, APCA):
  - `--bad` (#DC5455), the red for losses, negative EV and "down" chips,
    reads at **Lc 36–38**. That is under the Lc 45 floor even for large
    bold text.
  - `--text-mute` (#9E988B), the grey second line on every pick row,
    reads at **Lc 47–49**, under the Lc 60 bar for secondary text.
- **Why not fixed:** both change the look of the whole site. The grey is
  used 532 times and the red 94, and the tool itself calls it a palette
  decision. It is quick to do once you pick a direction: a brighter red
  and a lighter grey, before-and-after screenshots, your call.

## Checked and clean

- **Python correctness:** no undefined names, no unreachable code, no
  mutable defaults outside tests. Ruff flagged 44 closures defined in
  loops; each was read, and every one runs inside the pass that defines
  it.
- **JS correctness:** no errors beyond L-1 and L-2. The other "undefined"
  names the linter raised (`a2hs*`, `mcShowChart`, `ApexCharts`) are
  `window` properties, or a vendor global, it cannot see.
- **Runtime, 180 page loads:** 0 JavaScript errors, 0 thrown navigations,
  0 horizontal overflow, 0 "undefined/NaN/[object Object]" in visible
  text, 0 broken local images. Every console error was a data file that
  only exists on the box, or an outside site this container cannot
  reach.
- **Security:**
  - Passwords: scrypt (16 MB per guess) with constant-time compares.
  - Session tokens: random.
  - Session cookie: HttpOnly, SameSite=Lax, and Secure behind TLS.
  - Headers: CSP, frame-deny, nosniff, referrer policy and HSTS, in both
    the app and Caddy.
  - Static file paths are contained in the web root.
  - Per-address rate limits and body-size caps on every POST.
  - The payment webhook is verified by signature.
  - The owner token is compared in constant time and fails closed.
  - Ask requires a subscription when the paywall is on.
  - No injection path found (M-4 above).
- **Accessibility:** on 8 main views every visible image has alt text and
  every button and input has a name. The page declares its language.
- **Caching:** Caddy compresses (gzip, zstd). The shell revalidates, so
  there are no stale deploys. Live-score files skip the shared cache.
  Boards use ETags.
